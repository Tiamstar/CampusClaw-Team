# 新题库随机组卷审核

规约为 [QZ-002](../openspec/changes/add-core-teaching-loop/specs/quiz/spec.md)。Codex 对照选题中的按标签随机组卷与题库重构，发现新建的无分值题被旧随机规则排除。教师现在可在随机测验中按启用题型输入每题分值。选择知识点后，服务端只从相同课程、归属与题型的有效独立题中抽取，并把分值冻结到答卷。

| 检查范围 | 保证、实现或边界 |
| --- | --- |
| 接口入口 | 创建接口沿用任课教师权限和同课程知识点校验。规则分值最多两位小数，范围为 0.01 至 99999.99，验证后才写入草稿。 |
| 业务逻辑 | 随机发布和开考共用候选及题量检查。固定卷继续逐题设分，未配置规则分值的旧卷沿用题库分值。无答案题仍走人工评阅。 |
| 数据库 | 规则继续存于测验 JSON 字段，无迁移。分值写入新答卷快照，题库和已开考的答卷保持原值。 |
| 公共函数 | 复用现有 `score_value`、题库归属过滤、抽题和确定性评分服务。 |
| 错误处理 | 非法分值返回 400，候选不足沿用发布校验。题库在发布后发生变动时，开考仍可能因候选不足而拒绝。 |
| 安全隐私 | 继续排除非本人题库和材料题组，学生视图仍按原权限隐藏答案。 |
| 性能 | 按随机规则沿用每条规则的候选查询。允许分值为空使合格题池可能扩大，超大题库查询成本需单独测量。 |

需求覆盖和一致性由 QZ-002、旧规则回归和新评分路径共同核对。失败覆盖包含非法分值、标签和候选数。查询边界如上，无新数据库或评分实现。权限与高风险检查使用原有锁和快照边界，正式分数按该版本可回查。结论待队友独立复核。

```sh
docker compose run --rm --no-deps -v "$PWD/backend/core:/app/core:ro" backend python manage.py test core.test_quiz --noinput
npm --prefix frontend test -- tests/quiz.test.ts
```

队友操作入口为教师的“测验 → 创建测验”。可新建一道无分值独立判断题并挂知识点，使用该知识点和 7.50 分规则发布，学生开考及交卷后检查答卷得分、题库分值与旧答卷。用另一位教师的私有题或不匹配知识点复查候选边界。

2026-11-28 本机复验使用新建合成师生，真实 HTTP 13 个请求全部符合预期。课程 #3、测验 #1、答卷 #1 保留。未设题库分值的题按指定知识点进入试卷，冻结分值 7.50，保存正确答案后交卷得到 7.50、评分版本 1。学生开考响应未返回答案键，教师回读题库分值仍为空。前端定向测试 12 项通过。此过程未使用模型，也未代替队友独立操作。
