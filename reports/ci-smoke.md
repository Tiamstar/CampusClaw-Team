## 原问题与修复

旧`scripts/smoke.py`保存课程助手时不提供revision，当前接口会409；旧工具测试仍期待`ok`，当前正常结果应为`pending`，需要所有者显式确认才执行。旧finally还删除合成课程/账号，既丢失失败状态，也可能遇到已有PROTECT引用而掩盖原失败。这些为当前源码契约的不兼容检查；没有为了证明旧失败运行带清理的旧脚本。

新脚本读取当前配置revision后保存绑定。每个MCP工具依次检查pending、他人确认404、改参400、所有者确认succeeded、重放409，随后核对真实结果；隔离Python要求返回5050。模型仍为mock，真实部分是MCP协议和隔离执行，不宣称真实模型验证。

必须显式`--retain-fixtures`和指定新`--output`文件，只接受纯loopback HTTP入口与合法项目名，拒绝覆盖已有证据。通过项目标签定位唯一运行中的常规backend，先核对环境MODEL_PROVIDER为mock再创建账号；HTTP目录也再次确认mock。账号密码和初始化代码走docker exec stdin，不把密码作为`-c`命令参数；输出无密码/令牌或响应正文。请求状态和请求号逐步保存，任何失败非零且保留已创建记录，不自动重放不确定MCP操作或清理业务数据。

```sh
# 只在独立mock服务运行；每次选择新的证据文件。
python scripts/smoke.py --sandbox --retain-fixtures --output reports/smoke-new-run.local.json
# 使用另一独立项目时显式对应其loopback入口。
python scripts/smoke.py --project YOUR_PROJECT --base http://127.0.0.1:YOUR_PORT --sandbox --retain-fixtures --output reports/smoke-another-run.local.json
```

脚本从所选backend进程环境和HTTP目录两次核对mock，但不会读取整个Compose配置；运行前仍应确认入口与项目匹配。只支持本地HTTP冒烟；HTTPS专用验证使用`rehearse_https.py`，不能用放宽TLS校验代替。
