# 验收计划

版本：0.1 初稿。下列均为**待执行测试设计**，没有业务实测结果；本次规约校验不等于这些测试通过。

## 环境与结论

验收人使用独立工作目录、待验收提交、空数据库和自制夹具，不能复用开发者数据库或本地缓存。记录操作系统、依赖、数据库、队列、模型与检索版本、部署命令、公网地址、时区和提交号。密钥通过独立安全渠道注入，不进入录屏或仓库。

实现者先自测，另一位对同一提交和规约交叉验收。结论限定为：

- **通过**：主路径、失败路径、权限和证据均满足规约。
- **不通过**：已执行且观察结果违背规约，记录最小复现和实际输出。
- **阻塞**：依赖、环境、冻结指标或证据不足，不能判定；列明解除条件。

未执行不是通过；未纳入本轮的 P1 单独记录范围，不计入 MVP 通过率。单元测试和 API 测试不能代替公网端到端；录屏也不能代替数据库一致性和日志证据。

## 夹具设计

实现阶段须提供可重复、幂等的夹具导入命令。本节是夹具定义，不代表已有脚本或账号。

| 夹具 | 内容 |
| --- | --- |
| 课程 A / B | 互不共享成员与资料，课程/班级映射按底座明确建立 |
| T_A / T_B | 各自课程教师，无对方课程权限 |
| S_A1 / S_A2 / S_B1 | 两位课程 A 学生、一位仅属于 B 的学生；另有未登录会话 |
| S_A3–S_A8 | 统计测试补充匿名账号，不使用真实学生数据 |
| A 讲义 | 自制且含已知知识点、页码与一段提示注入文本；另有损坏文件与空检索问题 |
| 题库 | 五种题型、明确分值及等价答案、至少一个多知识点题；有非法和跨课程关联夹具 |
| 图谱 | K1 → K2 → K3 的先修链、候选环 K3 → K1、无答题数据的 K4 |
| 测验 | 5 题各 20 分；完整作答、未保存、过期、限次、并发与重复提交场景 |
| 成绩基准 | S_A1 作业 80/100、测验正式 90/100；S_A2 作业 50/100、测验 60/100；权重 30% / 70%，预期总评 87.00 / 57.00 |
| 统计基准 | 单独同快照 8 份正式答卷，总分 100/90/80/70/60/50/40/30，指定题满分 10，得分 10/10/10/0/10/0/0/0；正确率 50%，上下各 2 人区分度 1.00 |
| 异常注入 | 模型超时、限流、取消、任务重放、旧版本事件、断线、邮件与转换失败 |

成绩夹具需由真实评分流程建立并可复算，不在前端写死 87 或 57。统计夹具独立于两人核心演示，小于 8 人时区分度应为不可计算。

## 证据包与签署

使用 [验收记录模板](templates/acceptance-record.md) 逐项登记。每个包包含 `提交号 + 规约版本 + 环境 + 前置夹具 + 执行命令/动作 + 预期/实际 + 脱敏证据入口 + 验收人 + 结论`。

公开仓库仅提交脱敏小型文本和经确认可公开的样本；大录屏、真实日志和数据库备份放在双方可访问的受控存储，记录位置与校验值，不把密钥、真实学生信息或带凭据的下载地址写入 Git。

问题修复后用新提交重新执行受影响项及核心回归，保留原不通过记录；未解除的阻塞不能通过重命名为“待完善”消失。
