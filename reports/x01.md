## 执行方式与边界

构建并启动当前后端、forum-worker后，以现有教师/学生邮箱显式运行，输出必须选未使用过的路径：

```sh
docker exec campusclaw-team-backend-1 python manage.py verify_x01 --retain-fixtures --real --teacher TEACHER_EMAIL --student STUDENT_EMAIL --output /tmp/x01-new-run.json
```

该命令会创建新课程、新合成学生、作业、答卷、资料、评分及计划，不是只读回查或幂等导入命令；每次独立运行保留一套新记录。适用于明确授权的本地验收环境，不连接远程地址。教师需已具备创建课程资格，命令不会提升现有账号资格。所有HTTP使用服务器为这些账号签发的短期access JWT，不验证密码登录流程。模型服务需为真实配置，必须显式`--real`；计划由实际forum-worker轮询处理，不在命令中直接调用处理函数或伪造成功。

图谱前置数据为明确夹具：写入一份自制文本与预索引片段，人工编写有来源候选，再经实际教师HTTP审核接口批准，保留图谱版本1。没有执行Embedding索引或模型知识点抽取，不把该阶段记作真实抽取验证。建题、组卷发布、保存、交卷、正式评分、公开、总评、学情、图谱读取、计划创建和确认均通过实际HTTP；DB额外只读取评分修订计数及计划依据做核对。

候选与资料为本轮合成教学内容；简答分数由自动化命令以教师身份提交基准复核，不冒称另一位真人已逐题复核。复习模型只解释已经确定的步骤，实际模型标识为course-chat；后端与worker当时均配置openai提供方，镜像ID及命令SHA256留在证据中。既有worker镜像与新后端镜像不同，本轮只新增验证命令，没有修改worker业务实现；不声称所有容器已切到同一个制品。

## 实际检查

41项断言通过。四个独立HTTP连接经同一Barrier同时发出两份答卷各两次交卷，均200；每份只有一条自动评分修订。随后逐题复核产生修订2；重放修订1的评分请求409。保存同键重放恢复正确答案，旧版本保存409，交卷后写入409。未复核禁止发布，未公开评分不向学生返回；两个正式样本的区分度仍为null。

总评由HTTP正式来源重算，两个学生各只能看到本人一行；学情每份5条证据均回到本人答卷/评分修订2；图谱与同窗口学情版本和节点指标一致。两份实际模型计划均无提前提醒，经确认后生成6/3条唯一待办，旧确认重放409不多建。同学答卷、学情、私人计划及教师读取学生私人计划均403。等待worker最多180秒，观察超时只报错并保留任务，不盲目重跑任务。

## 七类与七维审核

| 类别 | 保证与依据 / 何时失效 |
| --- | --- |
| 接口入口 | 仅CLI，保留标志、real、loopback来源和新输出路径前置检查；无新线上路由 |
| 业务逻辑 | 以现有API走状态机，Decimal独立复算总评；并发HTTP不直接回写分数或绕过提交 |
| 数据库操作 | 合成账号与预索引/候选是明确前置夹具；业务阶段由服务端事务处理，源课程不改写 |

| 错误处理 | 状态不符或断言失败即非零，先写部分证据并保留记录；模型失败和超时不自动重试，不伪造成成功 |
