# 底座接入设计

状态：初稿；各项均为目标设计。

## 接入策略

1. 确认底座源码位置、版本、许可和可运行方式，记录不可直接复用的能力。
2. 对照 `course-core` 逐条核对，不以页面存在推断权限或异步任务已实现。
3. 优先复用身份、文件、检索、模型网关、任务与审计服务；新增模块通过服务接口接入。
4. 如果底座不是 Vue / Django，先共同评审接入成本，再决定适配或调整栈，不并行创建两套身份和权限系统。

## 授权链

请求认证 → 查询真实成员及任教关系 → 限定课程/班级查询集 → 校验角色和资源归属 → 执行业务 → 记录审计。后台 worker、检索过滤器、MCP 工具和文件下载同样执行此链；不能信任请求体中的 `course_id`。

登录态、CSRF / CORS 策略沿用并验证底座，不自行决定使用 Cookie 或 JWT；认证方案确认后补充对应安全测试。

## AI 边界

模型、Embedding 和外部服务密钥只在服务端加载。服务端构建工具白名单和可见资料范围，模型不能更改角色或权限。资料、答案、帖子都是不可信数据；引用需回查真实资料版本和页码/片段。

原有三项技能为解题引导、作业批改、错题讲解；新增技能由 P0 变更扩展。启停状态在任务执行时生效。MCP 只读工具最小化返回字段，写操作需要与用户、动作、参数、有效期绑定的一次性确认，确认后仍检查权限。

## 任务与追溯

使用统一任务 ID、请求 ID、发起人和课程上下文。任务状态采用 [共享契约](../../../docs/architecture-and-contracts.md)；取消、超时、重复执行和人工重试不得直接修改正式成绩或发布内容。

## 部署约束

未来应提供迁移、夹具、容器或等价安装说明、HTTPS、公网地址和健康检查。性能指标在环境冻结后确认；实际值、测试命令和时间窗口同时提交。真实外部 AI 调用与测试替身分开验收。

## 风险与回滚

- 底座缺失或不可运行：阻塞集成，提交缺口清单和补建评审，不伪称复用成功。
- 外部服务失败：保留可重试状态，不影响确定性业务数据。
- 错误数据迁移：先备份，在独立环境恢复验证后再推广；回滚不得删除学生已提交记录。
