# P1 扩展设计

## 启动和裁剪

P0 通过后，双方根据剩余课时确认 E2 / E6 / E7 的启动顺序和完整子范围。若整体裁剪，更新范围与验收矩阵；不移除底座主路径或 P0。已启动模块也不能只做页面而忽略权限和失败路径。

## 实时互动

会话与事件均带课程、活动 ID、事件序号和服务端时间。先持久化再推送，重连按最后序号补发或获取完整快照。签到由服务端校验窗口、码和成员；统计去重，补签需教师权限与理由。匿名沿用论坛对同学匿名、服务端留身份的约定。

## 文档与笔记

Office 在受限进程内转换 PDF，原件和衍生文件有同一权限边界。转换失败不影响下载授权原件。引用锚点使用资料版本与页码/片段；旧版锚点不可静默跳到新版错误页。笔记默认私有，阅读进度按资料版本保存，不向同学公开。

## 消息和日历

复用 P0 站内待办，以业务事件 + 接收人 + 渠道 + 周期作为去重键。邮件有排队、已受理、失败状态，不以服务商受理冒充实际阅读；退订可选提醒不取消必须保留的业务状态。iCal 以高熵只读令牌限制用户和课程，支持轮换撤销，不暴露他人日程或密钥。

数据库统一保存 UTC 时间，展示与订阅按明确时区转换；可重复事件的 UID 稳定，变更时提高版本序号。通知失败不能回滚已经成功的交卷、回复或出勤记录。
