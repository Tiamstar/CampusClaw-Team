# E4 学情诊断报告（GRD-004）

2026-11-16，Codex 实现与自测；不代表组员独立人工交叉验收。报告不改变正式成绩，不自动发布。本地课程、作答、成绩、图谱与复习计划均保留。

## 数据、任务与技能

教师为本课程学生选择最长366天的带时区窗口，创建持久化 queued 任务。同一教师/学生/课程仅一个排队或执行任务。现有 worker 每分钟有界认领至多3份，阶段为 read_evidence → generate_findings → render_exports → awaiting_review；模型和PDF制作在事务外执行。教师可取消排队、运行任务或草稿；超过5分钟中断任务标记失败。回写持有课程→报告锁，并再次核查教师资格、启停配置版本、学生成员资格和依据指纹；取消后的迟到结果不复活。

DiagnosticSettings GET 返回已有值或内存默认值，不创建业务记录；教师 PUT 需预期修订。停用阻止排队，配置变更或撤权拒绝运行结果进入复核，并阻止旧草稿发布。已发布报告不会因技能停用而自动撤回，仍可由发起教师显式撤回。

依据使用共享本人已公开正式评分与冻结知识点标签、已批准图谱、资料当前哈希/文件存在性、当前成绩策略及目标学生公开成绩项。成绩册为当前策略的本人成绩，知识点指标为指定窗口；界面/报告注明口径。未公开成绩不会进入模型或报告，未知不当零分。仅在测验答案公开时间之后才读取该学生的文本/选择/填空作答；不发送题库答案键、题目正文、图片字节或同学数据。报告从得分不能推导具体失分原因。

单次最多100知识点、200道有效题；模型结论最多30个有评分节点。learning-diagnosis@1.0.0 使用现有模型网关、60秒总时限、100000字符输入/50000字符输出。模型只输出结构化观察、建议和评分引用，不评分、不调用工具、不决定学生资格或结果。每条结论须关联本课程有正式评分的节点、至少引用该节点真实答卷/题目/评分修订；拒绝未知节点、空引用、伪造引用、重复节点和超长文字。无证据不调用模型，输出明确“暂无证据，不作诊断”的报告。结构/引用校验不能证明自然语言与数字推理正确，教师仍须逐条回查。

## 复核、版本与导出

教师可修改观察和建议，保留真实引用，输入理由后生成新的不可变 DiagnosticVersion。模型原草稿不被覆盖。HTML和PDF都从同一个 content/version/content_hash 与同一有序段落投影生成；PDF另有字节哈希。报告包含窗口、数据版本、公开成绩项/权重、知识点得分率/样本量、未知提示与具体答题引用。中文字体随PDF嵌入，逐行测量宽度、自动换行分页和页码，PDF上限6MiB。无模型生成HTML；所有文本转义，HTML无脚本和外部资源。

确认复核必须勾选全部结论、填写理由并携带 expected_revision；发布是独立操作，只允许已复核的当前版本，教师修订后强制重新复核。页面存在未保存修订时禁用复核和发布。发起教师可按每页20条回看版本理由及历史HTML/PDF，明确提示旧稿可能包含已纠正错误；学生仅看自己的已发布版本。撤回立即阻止学生读取内容和导出；导出没有公开直链，每次重新查成员及对象权限。

窗口内评分、作答公开状态、图谱或资料变化使报告过期，隐藏旧正文与导出并阻止发布，数据库仍保留历史。该指纹保守包含整个课程图谱，未涉及节点变更也可能要求重新生成。已经下载到设备的副本无法远程撤销。当前只允许发起教师管理本人任务，不开放同课教师互改报告。

## 实际接口与迁移

沿用 `/api/`：`courses/{id}/diagnostic-settings/` GET/PUT；`courses/{id}/diagnostic-reports/` GET/POST；`diagnostic-reports/{id}/` GET；`action/` POST（review/publish/cancel/withdraw）；`revise/` POST；`versions/` GET（仅发起教师）；`diagnostic-versions/{id}/html/` 或 `pdf/` GET。GET无外部调用与业务写入。列表每页20条。导出 no-store/nosniff，直接HTML响应设置CSP sandbox，文本转义。

迁移0015新增诊断设置、报告与版本三表，不修改教学数据结构。升级前备份 `.backups/before-diagnostic-20261116.dump`（仓库外）；独立 diagnostic_restore_20261116 恢复并迁移成功，验证2门课程、5份资料、9条复习待办及空的新表，随后只移除该临时恢复库。主库迁移和Compose健康检查通过。

## 真实账号验收与模型反例

教师账号通过真实API发起课程6、学生账号的诊断 #1；worker调用 course-chat 生成草稿v1。学生浏览器在发布前显示无报告。草稿把“题5得8/10”误写成“失分8分”，虽然引用 a1:q5:g2 真实，措辞仍错误。这验证了引用有效不等于结论正确。

Codex使用教师账号在界面回查8/10证据，将观察修订为“距满分差2分，无法仅凭分数判断具体原因”，建议限定为一般复习并等答案公开后回看作答；保存v2，原v1保留。逐条勾选、填写明确标注“Codex功能验收、不代表真人交叉验收”的理由后发布v2。该动作是两个用户授权账号之间的合成课程验证，不新增真实评分。

学生真实API及浏览器仅能读已发布v2，HTML/PDF X-Report-Content-Hash一致，PDF字节SHA256与数据库一致；请求原v1返回403。v2 PDF约1.71MB、1页，实际渲染检查中文、换行、页码和引用无裁切；自动用例另覆盖长中文多页。学生页面显示本人观察、建议、证据和同版导出，390px视口 documentWidth=375/content约335，无整页横向溢出，验证后恢复视口。HTML预览按钮成功新开报告标签；自动浏览器对blob URL导航有限制，未宣称对该标签进行完整视觉验收，PDF以本地渲染核查。

保留课程6、报告1的模型v1与修订v2、发布与审计、原两份答卷及正式成绩、图谱和9条提醒。截图在仓库外 `.diagnostic-teacher-validation.jpg`、`.diagnostic-student-validation.jpg`、`.diagnostic-mobile-validation.jpg`；导出核对文件 `.diagnostic-validation.pdf`、渲染图 `.diagnostic-page-1.png`。用户可在“诊断报告”查看、撤回或另发起草稿。
