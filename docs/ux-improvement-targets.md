# CampusClaw UX 改进目标清单

根据 2026-11-17 用户反馈，当前功能虽然完整但不够人性化。本文为下一轮优化设定具体目标，重点在**减少认知负担、流程直观化、反馈及时性**。

## 执行基线与状态（2026-11-17）

本文保留用户提供的七个方向。下文“当前问题”为调研时的假设，须按当前代码和实际操作逐项核实，不用代码行数判断功能是否存在，也不把目标等同已交付。

| 方向 | 当前核实与实施状态 | 后续验收重点 |
| --- | --- | --- |
| 一、题库组卷 | 已有图片/多照片/DOCX/PDF/TXT 识别、原卷编辑和来源索引；本轮统一题库列表选题路径，增加全卷统一设分、总分和缺参考答案数。题库列表已有答案状态。 | 选题篮/固定组卷已支持账号与课程隔离的标签页恢复；难度筛选、知识点建议待做；不可把模型识别成功当语义正确 |
| 二、答题批改 | 现有独立工作台已具题号导航、已答统计、倒计时、自动保存与 AI 逐题建议。不是无进度长列表。 | 自动保存已增加两秒成功提示；跨课程批改中心、按题对比、持久化发布通知 |
| 三、论坛答疑 | 现有搜索覆盖标题与正文；草稿已持久化、有引用片段与回查，已有置顶/精华。 | 回复全文检索与可重开的解决状态已实施；相似讨论自动提示和查看后返回编辑已实施；跨刷新发帖/教师草稿编辑恢复待做 |
| 四、个性学习 | LearningWorkspace 有真实评分证据和趋势；ReviewWorkspace 已支持提醒标记完成。不能称空壳或无完成按钮。 | 错题聚合洞察、相似题重做、个人仪表盘；无时长采集时不得编造学习时长 |

| 七、交付 | 按实际验证更新记录，保持教学数据。 | 逐项验收并继续迭代；两位组员独立验收仍待执行 |

本轮检查与限制见 `reports/review-ux-foundation.md`。本表是状态校正，不替代以下完整目标，也不表示七方向全部完成。

## 一、题库与组卷流程（优先级 🔴 最高）

### 当前问题

QuizWorkspace.vue 组卷逻辑极其复杂（280+ 行代码处理组卷状态）：

1. **选题流程不直观**
   - 学生点进"测验"看不到题库；需要教师进"管理题库"→"我的题库"→选择题目
   - 选题操作分散：可以"选此题组卷"、"加入选题篮"、"整组组卷"三条路，用户不知道用哪个
   - "选题篮"是一个临时状态管理器，但如果刷新就丢失

2. **题干输入太繁琐**
   - XLSX 模板格式硬性：题型|题干|选项(A)(B)等|答案(A、B)|分值|解析|知识点
   - 学生用"简答题"时，选项列留空，容易误操作
   - 知识点必须精确匹配课程已有的点，否则拒绝导入；没有"创建新知识点"建议

3. **分值设置分开**
   - 题库中题目无需设置分值（reason: "组卷时逐题设置"）
   - 创建测验时才逐题填分值，如果题目多，这个表单会很长
   - 如果后来改分值，需要新建一份测验

4. **答案键可选**
   - 题目导入时允许"答案待补充"
   - 等到批改时，没有标准答案，全部变成"主观题需人工批改"
   - 但系统显示时不清楚哪些题目缺少答案键

### 改进目标

**T1.1: 单一、线性的出题与组卷入口**
- 教师不再区分"题库管理""创建测验"
- 统一入口：进课程 → 点"测验"或独立"题库"tab → 看题目列表 → 选题 → 直接编辑分值 → 创建测验
- 或者：直接点"快速组卷" → 按条件筛选题目 → 所见即所得地组成一份卷 → 保存测验

**T1.2: 题库导入智能化**
- 支持"拍照导入"（用户拍试卷照，AI 识别题干/选项/答案）或至少"粘贴原文" → 半自动切分
- 保留 XLSX/DOCX 模板，但提供更好的**引导式表单**：依次填"题型选择" → "题干输入" → "选项输入" → "答案输入"，每步有示例和验证提示
- 导入时**自动建议知识点**（基于题干内容相似度）而非要求精确匹配；用户可选接受、编辑或跳过

**T1.3: 分值与难度集中管理**
- 题库编辑时可选填"难度等级"（简单/中等/困难）和"分值范围建议"（如：5–10 分）
- 创建测验时可按"推荐分值"快速填充，而非每题手填
- 后期支持"调整全卷难度"（难度偏易 → 提高简单题占比）的一键预设

**T1.4: 明确的答案键状态**
- 题库列表显示每题的"有参考答案""待补充"状态
- 导入或新增题目时，强烈建议填写答案键（而不是可选）
- 组卷时，提醒教师"包含 X 题无标准答案，需人工批改"

## 二、答题与批改体验（优先级 🟠 高）

### 当前问题

QuizAttemptPanel 和批改流程：

1. **学生做题没有节奏感**
   - 整个测验呈现为一个长列表，没有进度指示（第 N/M 题）
   - 自动保存成功后，只有一行文字显示"已保存到服务器"，容易忽略
   - 没有预估剩余时间的可视化倒计时

2. **简答题与客观题混用时体验混乱**
   - 同一试卷中，有的题是单选（自动判对错），有的是简答（待批改）
   - 界面没有清晰标明"此题需人工评分"vs"此题自动判分"
   - 提交后，看不到哪些题已自动评分、哪些待批改

3. **教师批改效率低**
   - AI 建议是一条独立的逻辑分支（点"AI 逐题评阅"后单独请求）
   - 如果有 50 份答卷待批改，一份一份打开，逐题填分值和反馈，工作量巨大
   - 没有"批量操作"（如：同一道题全部学生的答案对比、快速给分）

4. **反馈信息碎片化**
   - 学生交卷后，可能需要等待教师批改，但界面没有提醒"你的答卷已交卷，教师正在批改"
   - 批改完成后，没有邮件通知或应用内通知

### 改进目标

**T2.1: 答题进度可视化**
- 在左侧或顶部显示进度条：第 X/M 题，已作答 Y 题，未作答 Z 题
- 可以点击列表快速跳转到某一题
- 自动保存后，显示一个 2 秒的"✓ 已保存"toast，而不仅仅是文本

**T2.2: 题型标签与批改状态清晰分离**
- 每题显示"[单选] 已自动评分: 10/10 分"或"[简答] 待教师批改"
- 提交后，在成绩单页面显示每题的最终状态：自动评分结果、人工评分结果、未批改
- 学生能看到自己的错题原因

**T2.3: 教师批改工作台**
- 新增"批改中心"tab（不在当前课程tab内，而是全局）
- 列出该教师所有课程的"待批改答卷"
- 支持**按题目对比批改**：展示同一题的所有学生答案并排显示，教师快速给分（而不是逐个打开答卷）
- 支持**AI 建议批量预填**：一次性为所有答卷运行 AI 评阅，然后教师逐个复核确认

**T2.4: 批改完成通知**
- 教师发布成绩后，学生收到应用内通知"你在《微积分·第3讲测验》的答卷已批改，成绩 48/50"
- 提供直达链接查看详细批改反馈

## 三、论坛与答疑体验（优先级 🟠 高）

### 当前问题

ForumWorkspace.vue：

1. **帖子发现困难**
   - 相似问题检索是"可选"的，不是发布流程的一部分
   - 学生提问前，没有被引导查看历史讨论
   - 搜索框只有"按标题"功能，没有"全文搜索"

2. **AI 草稿流程繁琐**
   - 教师需要点"生成草稿" → 等待 → 逐项核对引用 → 编辑回答 → 确认公开
   - 中间如果网络中断，草稿可能丢失
   - 没有显示"该草稿引用的资料片段编号"方便快速回查

3. **没有分类与管理**
   - 所有帖子混在一起，按时间倒序
   - 没有"已解决" vs "待解决"的状态标记
   - 没有"优质答案"的标记或点赞机制

4. **知识点关联弱**
   - 发帖时可以关联知识点，但课程助手没有基于论坛讨论的知识点推荐
   - 学生错题后，系统没有提示"这个知识点在论坛有讨论"

### 改进目标

**T3.1: 发帖前的相似问题强制检查**
- 学生输入标题后，自动搜索相似问题并展示前 3–5 条
- 如果用户坚持发新帖，需要明确确认"我已看过上述讨论，问题仍未解决"
- 减少重复提问

**T3.2: 完整的全文搜索与过滤**
- 支持"搜索帖子内容和回复"（不仅限标题）
- 支持按"知识点""状态（待解决/已解决）""发布者（教师/同学）"过滤
- 搜索结果按相关度排序

**T3.3: 帖子状态与解决标记**
- 发帖时可选"已解决"或"待解决"
- 教师回复后，可选标记为"教师已答复"
- 支持"一键标记为已解决"，系统记录解决的回复 ID

**T3.4: AI 草稿的强化**
- 草稿生成后自动保存到草稿箱（即使教师没有立即确认）
- 显示"此草稿引用的资料：《微积分讲义》第 2 节第 3 段"，一键回查
- 支持"草稿变成私人笔记"（教师先收藏草稿给自己参考，后续决定是否公开）

**T3.5: 知识点 ↔ 论坛讨论关联**
- 学生在错题面板看到某个错题是"微分法则"知识点
- 系统自动推荐"论坛中关于微分法则的讨论有 3 条，最新回复在 2 小时前"
- 点击可快速查看讨论

## 四、个性化学习与诊断（优先级 🟡 中）

### 当前问题

WrongAnswerWorkspace、ReviewWorkspace、LearningWorkspace 都很简陋：

1. **错题没有洞察**
   - WrongAnswerWorkspace 只是列出错题，没有分析
   - 不知道"我在哪个知识点最常出错"
   - 没有"建议重做"功能

2. **复习路径形同虚设**
   - ReviewWorkspace 显示一个计划列表，但没有"标记完成"按钮
   - 没有进度条
   - 间隔提醒不清楚

3. **学情分析空壳**
   - LearningWorkspace 代码只有 26 行，没有真实内容
   - 学生不知道自己的学习进度、强弱项

### 改进目标

**T4.1: 错题分析面板**
- 显示"你在 5 次测验中共有 8 道错题，涉及 3 个知识点"
- 按知识点分组展示错题：例如"微分法则（4 道错题，错题率 67%）"
- 每个知识点下显示"建议复习时长"和"推荐资料"

**T4.2: 智能重做与反馈**
- 错题可以"重做"，系统会随机生成类似题目或从题库中推荐相似难度的题
- 重做成功后，记录进度；仍错误则提示关键知识点

**T4.3: 复习路径可交互**
- 支持"标记为已完成" → 系统记录完成时间、掌握度（题目做对率）
- 显示进度条和预计剩余时间
- 当一个知识点的复习完成度达 80% 时，自动推荐进入下一个

**T4.4: 个人学情仪表盘**
- 显示"本周学习时长""完成任务数""平均测验成绩""掌握知识点数"
- 图表显示知识点掌握度分布（条形图：已掌握、正在复习、待复习）
- 趋势线显示"最近 4 周的成绩变化"

## 五、前端架构与 UX 基础（优先级  🔵 中等）

### 当前问题

这些影响所有功能的整体体验：

1. **没有全局通知系统**
   - 所有模块共享一个 `message` ref，消息会互相覆盖
   - 无法同时显示"资料正在索引中""批改已完成""新消息 3 条"

2. **加载与骨架屏缺失**
   - 各模块加载时只显示"正在加载…"，长时间加载时页面是空白
   - 体感很慢

3. **错误提示不一致**
   - 有时是红色 `.error` 文本，有时是浏览器 alert
   - 用户不知道是临时错误还是永久问题

4. **移动端适配差**
   - 16 个 tab 按钮在 375px 屏幕上无法正常显示
   - 成绩表、答题卡等组件有横向溢出

### 改进目标

**T5.1: 全局 toast 与通知系统**
- 实现 toast 队列（同时可显示多条，自动消失）
- 区分成功/警告/错误/信息四个级别
- 支持"操作完成"的及时反馈（如：题目已保存、成绩已发布）

**T5.2: 骨架屏与加载状态**
- 各工作区加载时显示对应的骨架屏（灰色占位块）
- 例如：题库加载时，显示 5 个"题目卡"形的占位
- 异步操作进行中时，显示进度百分比或脉冲效果

**T5.3: 一致的错误处理 UI**
- 统一用 toast 系统显示错误
- 对于"不可恢复"的错误（如：权限拒绝、资源不存在），显示一个警告面板而非单行文字
- 提供"重试"按钮

**T5.4: 响应式设计全覆盖**
- 16 个 tab 在移动端改为"更多"菜单
- 成绩表支持横向滚动或改为卡片视图
- 答题卡支持竖屏下的单题放大视图

## 六、快速赢（低投入、高收益）

### 最快能改进体验的 5 个改动

1. **添加进度指示**（预计 2 天）
   - 在 QuizAttemptPanel 顶部加进度条：X/M 题
   - 效果：用户知道自己做到哪里，减少焦虑

2. **题库列表添加"无答案"标记**（预计 1 天）
   - 在 QuestionContent 旁加一个标签："答案待补充"
   - 效果：教师一眼看出哪些题需要补充答案

3. **自动保存的可视反馈**（预计 1 天）
   - 将"已保存到服务器"改为 2 秒 toast："✓ 已保存"
   - 效果：学生更有信心，知道答案没丢

4. **论坛帖子加"已解决"标记**（预计 2 天）
   - 在 ForumPost 加一个 checkbox："标记为已解决"
   - 列表中用不同颜色（或感叹号）区分
   - 效果：论坛不再是一堆废话，用户能快速找到有答案的讨论

5. **错题分组展示**（预计 2 天）
   - 在 WrongAnswerWorkspace 改为按知识点分组
   - 显示"微分法则（4 道错题）"
   - 效果：学生能看出自己的薄弱项
