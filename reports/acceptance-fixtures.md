## 实现与证据

新增`seed_acceptance --allow-synthetic-fixtures`。首次仅接受无账号/课程的PostgreSQL库，密码从环境读取且按既有强度规则校验，所有邮箱为example.invalid合成地址。T_A/T_B仅有业务教师能力，没有管理员权限。原教学库不运行导入或迁移，本轮既有本地服务继续健康。

初始化经进程内真实业务视图执行保存、交卷、复核、成绩公开、策略/快照及图谱审批。不是实际HTTP或密码登录证据；后续隔离实跑另以真实HTTP验证。预索引讲义和图谱候选显式人工编写，不调用模型、Embedding、SMTP或worker；损坏PDF只作为待索引输入，未伪造一次“索引失败”。外部故障、断线、取消、并发交卷等留给验收者/已有专项回归执行。

新增0023迁移只创建版本化回执表。PostgreSQL事务级锁串行化导入，业务和回执同事务；有回执则只返回原清单，不刷新时间、恢复删除资源或覆盖人工编辑。普通业务请求不取此导入锁，因此只在受控独立空库导入。文件存储非事务，中途失败可能留下合成附件，已在操作说明明确，不声称媒体原子回滚。

5项专项通过：未显式选择/已有账号拒绝；弱/缺失密码拒绝且不回显；注入业务失败回滚数据库和回执；全量基准/权限/环及过期负例/人工编辑后重复只读；两个并发导入者只创建一套。全量路径还用网络与SMTP拦截器确认没有外部调用。首轮失败来自测试错误引用不存在的模型网关路径；改为拦截实际httpx网络与SMTP入口后通过，没有删减业务断言。

独立Docker演练使用内部网络、全新PostgreSQL与无真实凭据的后端，不映射任何端口：

- 第二次导入返回同一清单，前后**77张表逐表内容摘要与所有3个媒体文件摘要完全一致**。对比在启动真实HTTP观察之前完成，后续登录本身会正常产生认证/请求记录。

## 七类审核

| 类别 | 保证、实现和边界 |
| --- | --- |
| 接口入口 | 只提供管理命令，无新HTTP路由；显式参数、空库和密码前置检查 |
| 业务逻辑 | 分数经现有视图，不直接插入成绩；人工候选/预索引不混作AI证据 |
| 数据库操作 | 唯一回执与事务锁防重复，失败回滚；普通注册并发须由环境隔离避免 |
| 公共函数 | SeedAPI统一状态校验，不打印响应体；清单集中资源定位，不写死主键 |
| 错误处理 | 非预期HTTP立即非零；不写成功回执；媒体非事务边界明确 |
| 安全隐私 | 合成账号、环境密码、标准哈希、无管理员/外部服务；拒绝已有真实账号库 |
| 性能 | 仅离线初始化，约3秒专项主体；一次事务含本地业务/密码散列，无外部网络 |

七维：需求覆盖为幂等初始条件及明确待注入场景；一致性由正式评分版本和独立统计快照复算；失败路径覆盖拒绝/回滚/重复/并发；查询性能为离线有限11账号/16答卷，不扩展生产查询；重复逻辑复用业务接口；漏洞风险以禁止覆盖/凭据隐藏/合成身份约束；高风险为把夹具当成验收结论或误用真实库，说明、拒绝与回归分别防护。结论为本地可用，等待另一成员在同一提交的独立环境执行。
