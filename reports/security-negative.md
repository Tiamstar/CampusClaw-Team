## 七类检查

| 类别 | 依据与边界 |
| --- | --- |
| 接口入口 | 验证器只允许loopback HTTP、显式retain和既有两个授权账号；生产入口/路由不改变 |
| 业务逻辑 | 正常/恶意对照、存储与渲染分开；API JWT与后台CSRF语义分开 |
| 数据库操作 | 合成对象经现有API创建，正式成绩仅只读对比，失败夹具保留；不做迁移 |
| 公共函数 | 固定JSON语料供HTTP及前端组件回归共用，现有权限/渲染器复用 |
| 错误处理 | HTTP不符明确失败并保留部分证据；后台未就绪不自动重放写请求 |
| 安全隐私 | 不输出JWT/密码/原始成绩，合成正文可公开；不存在账号验证CSRF，不修改真实账号凭据 |
| 性能 | 有界4组SQL和15秒请求超时，无负载扫描，不以SQL响应时间推断容量 |

## 七维审核

| 维度 | 自审结论 |
| --- | --- |
| 需求覆盖 | 固定SQL/XSS/CSRF反例、正常/失败对照及保留数据已提供，非完整渗透测试 |
| 一致性 | HTTP状态、数据库只读完整性与浏览器DOM各自取证；不把存储原文当作XSS失败 |
| 失败路径 | 后台403、API401、有令牌正常对照、SQL非空集/他课隔离，静态资源测试故障实际修复 |
| 查询性能 | 既有ORM参数化与字面匹配；未新增生产查询或性能结论 |
| 重复逻辑 | 回归和固定语料集中，未新增第二套认证/净化逻辑 |
| 漏洞风险 | 未绕过CSRF/认证或禁用审计；原中危开发依赖保留，编码变体/其他入口继续可扩展 |
| 高风险场景 | 整体成绩只读比对、验证数据不删除；其他用户并发评分会导致完整性检查失败，需安静窗口复验 |
