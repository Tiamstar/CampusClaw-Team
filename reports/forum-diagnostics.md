# 答疑草稿失败分类

2026-11-16，Codex实现与自测，关联FRM-003、SEC-003。X02草稿5只留下通用失败提示，本轮补充可排查且不泄密的分类；没有新增依赖或迁移，不更改旧失败，也不宣称查明草稿5原因。

## 行为与兼容

原草稿API保留status/error，新增教师专用error_code。页面沿用错误区域显示中文处理建议，不堆叠技术码。无错误为`''`，旧failed为`legacy_unknown`，GET不写库。新错误以固定中文文案存入已有error字段，读时按映射还原；将来修订文案须兼容旧映射，否则保守退回未知，不允许猜测原因。

| 分类 | 处理建议 |
| --- | --- |
| retrieval_error | 检索失败，稍后重试或人工回复 |
| model_timeout / model_rate_limit | 模型超时/限流，未公开，可稍后重试 |
| model_service | 维护者检查服务，不展示服务器详情 |
| output_limit | 缩小问题范围或人工回复 |
| invalid_json / invalid_schema | 模型格式或字段无效，未公开 |
| invalid_source / citation_labels | 引用不在检索资料/标记不一致，阻止草稿并人工核对 |
| state_changed / permission_lost | 设置/权限变更，迟到结果不采用；撤权后接口403 |
| interrupted | 超过5分钟running由原扫描服务标记中断 |
| internal_error / legacy_unknown | 未知异常安全提示；旧失败保持未知 |

检索错误不混作模型故障，HTTP429与网络超时分别识别。模型返回数组/null显式判字段无效。原有长度、JSON、字段、来源和引用标记校验保留，不因分类放宽。无命中仍为no_evidence；任何failed均不能发布。权限在返回前再次检查。

从running实际转为failed时写forum.draft.failure审计，仅含资源/课程/操作者ID、请求号和固定分类，不记录str(exception)、URL、响应体或失败模型输出。条件更新不覆盖别的终态。扫描中断沿用批量恢复，只保存固定文案，不伪造原请求的模型错误审计。

## 七类及七维审核

| 类别 | 依据与边界 |
| --- | --- |
| 接口入口 | 原路由/状态机，新error_code兼容字段，返回前重查权限 |
| 业务逻辑 | 只变更running草稿，无公开回复或改分；无依据不是异常 |
| 数据库操作 | 复用error，无迁移/旧失败回填，条件更新防终态覆盖 |
| 公共函数 | 固定映射与typed异常集中定义，仍兼容ValueError |
| 错误处理 | 检索/调用/解析/引用/状态分开，无法判断保持未知 |
| 安全隐私 | 仅固定文案与元数据，教师专用，无失败输出或异常详情 |
| 性能 | 无额外模型调用，失败多一条元数据审计，GET只映射 |

七维：需求覆盖FRM-003可识别失败；一致性不变更旧终态和只读GET；失败路径由异常注入证明，真实成功另标；查询性能无新扫描；重复逻辑共用映射；漏洞风险为异常泄露与撤权迟到返回，均有负例；高风险为误将校验失败当语义抗注入，明确禁止。固定分类不是语义判断或完整监控系统。
