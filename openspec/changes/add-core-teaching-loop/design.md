# P0 教学闭环设计

## 模块和共享边界

规划 `quiz`、`forum`、`gradebook`、`knowledge` 四个 Django 模块。各模块写自身聚合，跨模块通过服务层和可重放事件协作；不让智能体直接写成绩表。`knowledge` 提供稳定知识点 ID，`quiz` 提供评分版本，`gradebook` 负责成绩快照与分析。

共享口径以 [数据契约](../../../docs/architecture-and-contracts.md) 为准；真实底座接入后再冻结 URL、字段和迁移。

## 测验一致性

- 发布前校验组卷规则，开考时生成包含题目版本、顺序、分值、答案规则和知识点的服务端快照；答案键不返回学生端。
- 作答按 `attempt_id + answer_version` 更新；事务内同时检查状态、服务端截止时间与版本，冲突返回当前版本。
- 人工交卷与自动交卷竞争同一行锁或等价 CAS，只有首次合法状态转换生效。队列至少执行一次时仍只能生成一条正式提交与对应版本成绩。
- 截止时间为统一关闭时间与个人限时截止的较早者，客户端计时仅展示；worker 延迟不延长答题窗口。
- 修改题库不影响已开始试卷；最终答案不可再改，教师可基于审计修订评分结果。

## 评分和成绩

客观题使用冻结规则。简答及无法确定匹配的答案先待复核，AI 建议单独存储，教师确认后产生新的正式评分版本。成绩同步使用来源 ID + 评分版本去重，回放旧事件不覆盖新版本。权重与多次测验取分均有策略版本，修改需重新计算并记录原因。

## AI 草稿和知识图谱

AI 输出只落草稿，必须保留资料引用、运行 ID 和数据快照。教师审核发布论坛答案和知识关系；生成诊断报告只能读取授权成绩与答题证据。报告生成期间源数据变化时标记快照时间，不伪装为实时结果。

先修关系使用 PostgreSQL 关系表，审批时检测成环；无可评分证据的知识点为“未知”，不是红色低掌握。复习路径由确定性先修排序和薄弱点集合约束，智能体负责组织步骤与解释，不得改写正式成绩或替代教师校对。

## 降级与撤回

模型不可用不阻断保存答案、交卷、人工评分或人工答疑。诊断与抽取失败保留草稿，取消后的迟到结果不能发布。删除资料后旧引用标记失效，撤销图谱关系生成新版本，不删除历史答题和证据记录。
