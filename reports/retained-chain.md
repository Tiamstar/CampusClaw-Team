## 可复现命令

先构建并启动backend且健康检查通过，使用明确授权的既有账号执行：

```powershell
docker compose build backend
docker compose up -d --no-deps backend
docker exec campusclaw-team-backend-1 python manage.py verify_retained_chain --teacher TEACHER_EMAIL --student STUDENT_EMAIL --course-id 6 --snapshot-id 1 --plan-id 2 --draft-id 2
docker cp campusclaw-team-backend-1:/tmp/retained-chain-evidence.json reports/retained-chain-evidence.json
```

如果用户随后改分、调整计划、撤回公开或修改图谱，失败是合法的当前状态证据，不应为了让验证器变绿而回写旧记录。每次覆盖输出前应另存旧报告。只读回查没有跨请求强一致数据库快照，并发业务变更可能使检查失败，需要安静窗口复验；本轮不修改生产一致性语义。

## 七类与七维自审

| 类别 | 依据 |
| --- | --- |
| 接口入口 | 显式既有账号/课程/对象ID，复核真实Membership，不扩大权限 |
| 业务逻辑 | 从原答卷评分回查快照/学情/图谱/路径，论坛回查确认及待办；不替代新流程运行 |
| 数据库操作 | ORM只读选定对象；不创建/删除教学数据，不迁移 |
| 公共函数 | 复用当前API与sources_current；总评独立Decimal复算 |
| 错误处理 | 非200或不匹配非零退出并保留部分证据，不自动修改夹具 |
| 安全隐私 | JWT仅内存，报告元数据；教师不能读取学生计划 |
| 性能 | 固定一门课与四个对象，无负载扫描；未测并发容量 |
